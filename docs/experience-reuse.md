# 跨任务经验：实现与验收边界

更新：2026-11-19。模块为 `runtime/robot/experience.mjs`；编排在 coordinator，Runtime 提供鉴权的 `GET /episodes/{id}/trace`。

## 解决的问题

任务内恢复已经能依靠模型及当前历史完成。这里检验的是：先前任务中独立验收通过的修复，能否在新任务中减少重复试错。外部经验不会修改模型参数，也不能替代当前感知或最终验收。

目前提取器只识别一个预定义形状：支撑物未知导致释放被拒绝 → 沿 Runtime 记录的竖直路径撤回 → 公开确认仍持有 → 新支撑证据可用 → 最终公开验收 verified。它是有验证条件的案例复用基础设施，不是通用技能发现。保留源任务、源码摘要、证据事件 ID 与完整轨迹摘要；不把旧坐标、旧 Python 或模型原文放入经验建议。

## 闭环

1. 关闭任务后，工作台从 Runtime 获取有限公开 trace；活动场景拒绝导出该 trace。服务重启后缺少原来源信息的历史 trace 也拒绝，不能用新源码替旧执行背书。
2. 提取符合完整证据链的候选，写入 candidates。候选不会自行成为可检索经验。
3. 离线独立评分通过后，显式导入匹配的验证凭据，写入 validated。首轮从旧 stack/62 导入一条成功修复，持续遮挡未完成记录跳过。导入器校验冻结源码、评分器、任务关闭及物理/公开结果，不读取 evaluation-private.jsonl。
4. 新任务先获取 Runtime 来源，再获取观测，在图片下载前检索。仅当前支撑未知、记录撤回可用、夹爪闭合、目标与版本一致、预算足够且 API/传感器语义兼容时命中；禁止同任务自检索。
5. 提供绑定到“当前恢复选项”的参数化建议，模型仍生成受限短代码。取消/换目标会作废迟到检索，旧回复不能派发动作；完成仍由 Runtime 验证。
6. 每次检索记录语料摘要、匹配/拒绝原因、证据引用、新鲜度与时间成本。经验可撤销；损坏、修改或缺验证的记录拒绝使用。检索及来源查询各有两秒上限，不因存储故障卡住控制环。

## 新鲜度

跨机器不能直接用桌面时间减 Runtime captured_at 来判定一秒窗口。使用服务端 age_seconds 加整个观测请求 RTT，再加响应后本地单调时间，作为保守上界。来源查询提前到观测前，检索提前到图片下载前。缺少年龄、年龄为负或上界超过一秒均不命中；证据阈值未放宽。

相容性摘要包含主动取证、CaP 后端、持有检查、放置验证、公开传感器及竖直撤回六个模块的内容哈希与契约版本。源码不兼容时先拒绝经验；它不是跨硬件安全认证。底层取消、预算、动作守卫和最终验收始终独立执行。

## 开关和实验
