# 下一项：有进展约束的恢复与退出

状态：最小实现和两项真实模型故障诊断已完成；当前开发版补充修正仍需完整模型回归。优先于扩大经验库或微调模型。

## 问题与证据

作业 20766 表明，主模型已经能在一次可恢复执行器释放后重新抓取并完成原目标；但持续缺少红色 RGB-D 时会重复观察和定位，直至用完 12 次决策预算。安全拒绝不等于有效恢复，预算耗尽也不等于及时自主请求帮助。

第一步已补充执行边界：全段名称检查阻止错误代码执行前半段；新一次未确认身份的抓取使旧抓空判断失效。这些保护不能替代下一项的恢复决策。

## 最小改动

仍使用一个主模型，在当前 episode 增加结构化恢复记录，不增加 Agent、训练或长期记忆。

每次恢复记录：被阻塞的目标事实、公开证据引用与时间、原始错误类别、已尝试技能和参数、实际执行结果、新证据是否改变判断、剩余可用恢复路径及预算。保留因果状态；看不见物体不能直接归因为物体丢失、夹爪故障或传感器故障。

| 已知情况 | 允许的下一步 | 验收依据 |
| --- | --- | --- |
| 代码名称或调用非法，尚未产生动作 | 根据具体报错修正代码 | 新代码通过执行前检查；不能原样重复 |
| 公开证据持续否定先前持有关系 | 等待保持确认，重新观察，满足条件后重新抓取 | 新鲜持有检查；旧结果和旧计划均不可沿用 |
| 支撑物或持有身份 unknown | 尝试尚未用完、适用条件满足的受限取证路径 | 新观测改变所需事实的证据状态 |
| 无新证据且没有剩余适用取证或修复路径 | 保持并请求用户协助 | 主动说明缺少什么证据；不等待总预算耗尽 |

进展由相关事实与验证结果判断；新 frame ID、时间推进或模型改写解释不算证据进展。记录重复请求和重复失败，结合技能原有次数上限阻止循环。新计划必须基于当前目标版本，停止、换目标及原有总预算继续优先。

## 实施和测试顺序

1. 先做可复现 fixture：同一 unknown 多次换帧、相同非法代码、一次恢复成功、两个有限取证动作仍 unknown。验证进展判断不会把新时间戳当新信息，也不会提前终止尚有有效取证路径的任务。
2. 接入主模型上下文和任务记录，测试非协作迟到模型回复、取消和换目标。保持 Runtime 为动作与验收的权威来源。
3. 用新冻结版本重做模型故障诊断，可恢复与持续未知分别报告；固定模型、预算和故障协议，原始记录完整保留，全部关闭后才独立物理评分。

主要验收：可恢复条件仍能完成；持续未知在有限取证路径耗尽后请求帮助，零未知证据下放置、零错误完成、零旧版本迟到动作；比较无效重复数、总决策数和墙钟时间。不能仅因更早停止就宣称更强恢复，也不能把系统强制截止记为模型自主请求帮助。
