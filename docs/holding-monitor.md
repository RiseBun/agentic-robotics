# 独立公开持有监控

目的：模型等待或代码执行期间，发现此前已验证的持有关系被后续公开观测持续否定，先保持，再让模型重新决策。

## 机制

- `CAP_HOLDING_WATCHDOG=1` 显式开启，默认关闭；仅覆盖现有红绿方块公开持有关系。
- 只有 `check_holding` 返回 verified 才布防；重复检查不重置累计观察窗口。
- 控制循环读取已经发布的 RGB-D/FK 状态，不发起渲染、RPC 或模型请求。保留原持有阈值，并要求布防之后完整、连续、同任务且新鲜的公开窗口。
- 仅当整个窗口持续支持“物体仍在初始低处，而 TCP 已处于高处”时触发。遮挡、混合证据、缺帧、过期、窗口不足均为 unknown；这项规则不覆盖所有滑落，也不能诊断碰撞原因。
- 触发后取消当前代码、更新相关状态版本、请求保持当前关节和夹爪命令。控制循环确认切换后，单独记录保持确认和延迟。
- 保持未确认时拒绝新决策、代码和完成验收；模型挂起请求可被监控事件放弃，即使模型接口不响应取消，迟到代码也不得执行。
- 新鲜公开检查重新确认持有后才重新布防；正常释放解除布防。整个过程不复位环境、不清零预算。

事件为 `public_holding_contradicted`、`public_holding_hold_confirmed` 和 `public_holding_monitor_rearmed`。`runtime_alert` 是 Runtime 权威状态，不是模型推断。

## 验证与边界

开发测试覆盖视觉反证、仍然持有、遮挡未知、单帧和缺帧、混合任务、旧帧、正常释放、运动中断、等待模型时中断、保持确认前禁止派发和迟到回复失效。测试不证明真实滑落检测能力。

物理诊断使用新冻结版本，覆盖无故障、注入执行器释放、红色 RGB-D 像素丢失。执行器释放会在真实仿真中打开夹爪，传感器故障只屏蔽公开像素；两者分开报告。独立真值仅在全部任务关闭后评分。实验代码中的等待／故障注入 API 不进入产品工具清单。

该阶段尚未完成：真实碰撞检测、扭矩／力传感器、进程卡死保护、真机急停和跨硬件标定。不得用当前视觉规则代替这些能力。

三项限定物理诊断已通过，全部关闭后独立评分。执行器释放触发并取消旧代码，红色像素缺失保持 unknown，无故障继续执行。故障至触发约 2.087 秒，触发至保持确认约 0.041 秒。详见 [结果与边界](../research/agentic_holding_monitor_20261119/v2/结果与边界.md)。

后续作业 20766 已完成两项真实模型诊断：可恢复执行器释放后，模型自主重新抓取并完成原堆叠目标；释放并持续丢失红色 RGB-D 时，模型未完成，公开 unknown，最终耗尽决策预算。两项均在模型等待期间被监控中断，旧请求失效、旧版本 API 为零，未复位环境。没有及时主动请求帮助的证据。它们各一次，不能推广为一般恢复率；详见 [主模型恢复结果](../research/agentic_holding_model_20261119/v2/结果与边界.md)。

恢复边界补充：未确认持有身份时，新一次关夹爪在派发前失效旧持有检查结果，避免沿用先前“抓空”记录允许释放。即使关夹爪超时，旧记录也不能重新生效；重复关闭已验证持有的夹爪不重置身份或视角预算。此修改有失败复现及开发回归，未包含在上述模型物理冻结中。

后续恢复策略诊断作业 20777 已包含该抓取失效修正：可恢复条件自主重抓并完成，持续 RGB-D 缺失条件主动请求帮助并确认保持。两条件各一次，均在模型等待时触发监控；活动代码期间的主模型恢复仍缺证据。开发版又补充当前 Runtime 视角次数元数据和位置容差，未纳入这两项模型冻结。[详细结果](../research/agentic_recovery_progress_20261119/v1/结果与边界.md)。
