# Agentic Robotics：能力缺口、依据与改进实验

日期：2026-11-18。本文区分已有证据、当前实现与待验证假设。它不是新的成功率报告。

## 从需求出发

目标是机器人在真实物理状态持续变化时完成任务，能被打断，能识别失败并恢复，并逐步复用经验证的经验。多 Agent、更多工具、模型微调都不是这个目标的必要条件。

现有系统已有单模型分段决策、唯一物理控制线程、同场景恢复、公开三值验证、停止确认、累计预算和完整记录。三个 seed=0 的研发成功样例来自不同修订，不能合并为成功率。当前瓶颈是可验证的可靠性，尚非架构模块数量。

契约、记忆和失败恢复已有大量工作。把它们接进系统属于必要建设，不能单独当作研究创新。后续研究应检验：在同一预算、模型和任务分布下，证据驱动的恢复与经验复用是否降低重复失败，并在新初态保持收益。

## 本轮实现：阶段验收与失败证据

`run_code` 可携带 `contract`，条件只支持已有公开目标关系；不允许模型定义自己的判断代码、读取真值或修改阈值。

```json
{
  "subgoal": "将已抓住的红方块放到绿方块上",
  "contract": {
    "preconditions": [{"holding": "red cube"}],
    "postcondition": {"on": ["red cube", "green cube"], "empty_gripper": true}
  }
}
```

- 前置条件为 failed 或 unknown 时，整段不派发任何公开 API。条件检查不重置环境或累计预算，也不是持续碰撞保护。
- 执行 completed、阶段 `stage_verification`、最终 `goal_verification` 分开。例如抬起阶段可以 verified，而最终堆叠仍 failed。
- 尚不能验证的接近／闭爪阶段允许不声明后置条件，其阶段效果保留 unknown。不能用代码完成冒充抓取成功。
- 每次 API 的 started/result/error 共享 `call_id`，通过任务、代码段、观测引用关联。MotionError 保留关节误差与步数；unknown 保留为证据不足。
- `feedback` 给出观测到的类别、阶段、接口、证据及时间；`causal_status=not_established` 明确这些不是已证实的物理根因。
- 验证器报错或返回非法结果时记录异常并返回 unknown，不把任务卡在 active 状态，也不接受成功声明。

这些条件仍受已有红绿方块 RGB-D 验证器的适用范围限制；没有增加接触传感器、通用支撑面识别或跨物体能力。

## 可重复实验入口

工程工具位于 `runtime/scripts/robot-campaign.mjs`、`campaign-host.cjs`；不进入产品发行导入图。它们使用独立任务目录和独立 Electron 加密身份副本，只读原用户数据库中的模型配置，实验不覆盖用户当前任务或连接设置。

实验计划固定任务、种子、重复次数、模型渠道参数、生产源码哈希与远端 Runtime 源码哈希；远端另记录 CaP-X 源码摘要、提交和 Python 版本。冻结源代码发生变化则停止后续试验。外部感知服务配置还需随作业脚本一并披露；模型服务商内部版本不可由本工具冻结。

中断试验不会静默重放代码。重新运行先查询原环境，能确认并停止后才记为 interrupted；网络暂不可达时保留待检查状态。无权威 episode 身份的中断不能自动继续。所有完成、失败、求助与基础设施异常都保留，不能只挑成功样例。

每个任务累计仍为 12 次模型决策、40 次公开调用、1500 个运动步、300 秒墙钟。任务结束后追加 1.2 秒无动作观察，用于独立稳定性检查，单列其成本。

独立脚本 `cap-runtime/tests/score_campaign.py` 只在执行后读取私有真值。公开完成声明与私有判断分别报告；稳定性只覆盖所记录的结束后窗口，缺少样本则 unknown。对齐使用 Runtime 自己的事件与采样时钟，不假设两台机器时钟一致。

本轮做 seeds=11、12 的三任务诊断，不做统计显著性或跨任务泛化结论；它们在本轮没有用于修改决策／控制策略。旧 seed=0 调试记录单独保留。

旧版对照只替换 server.py 以支持共同的源码身份核对，旧核心执行器、适配器、验证器、模型提示词和协调器保持冻结。两版本在 6 组任务／种子上的结果为：候选版独立成功 5/6，基线 6/6，均无误报完成；初始物体位置逐对一致。候选版 seed=12 重堆叠放置偏移后修正抓取失败，耗尽 12 次决策。两个版本先后运行、每组一次模型采样，仍有模型随机性与顺序混杂，不能把耗时或成功差异归因于阶段契约。

这轮结果不支持“多加契约就更强”的结论。保留契约的语义正确性与可观测性改进，候选构建单独保存；下一步优先重复对照和定位几何／动作瓶颈，不宣布成功率提升或进行自动经验晋升。5/6 和 6/6 都只是这 6 次的计数。

## 后续门槛

1. 固定版本多种子试验与错误完成声明统计，识别主要失败层；保留基础设施故障，不与动作失败混淆。
2. 在相同初态和预算下做旧版／阶段证据版配对比较，测恢复、误拒绝和额外观察成本。
3. 只有阶段证据可靠后，才从真实轨迹产生恢复经验候选，经过验证种子、回归与版本回退再晋升；先对比有／无经验检索。
4. 在公开传感器上实现动作无进展、物体滑落等持续监控，再做仿真故障注入和真机安全层验收。
5. 对第二种机器人做适配与验收，才能声称跨硬件。接口分层只是准备条件。

当前未实现经验飞轮、模型微调、持续学习或 RSI。以上每一步都需要实际结果，不能用设计图或日志替代。
