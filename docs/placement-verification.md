# 动作后主动验收：实现与验收边界

更新：2026-11-19。目标是打通“动作结束 → 当前证据不足 → 主动获取新证据 → Runtime 重新验收”，不把代码完成、可见性恢复或旧图像当作任务成功。

## 当前实现

新增受限 API `inspect_placement(top_name, support_name)`，仅接受当前最终目标中的红／绿方块关系。`CAP_PLACEMENT_EVIDENCE=1` 显式启用；与 `CAP_ACTIVE_EVIDENCE=1` 独立。Runtime 健康信息、公开观测 capability 和模型 API 说明保持一致，默认不自动启用候选。

技能先要求同一个新鲜传感器包中的张开命令和实测夹爪开口；没有该证据时不移动。当前关系已经公开 verified 或 failed 时直接返回，不为了取证额外移动。

当前关系 unknown 时，只有以下条件均满足才尝试侧移：

- 有当前最终物体的成功释放记录，之后未换目标、未重新闭合夹爪。
- 当前观测晚于释放；机械臂保持释放姿态，已沿竖直方向撤离。
- TCP 比释放 TCP 及公开可见场景上界都至少高 10 cm。
- 单次释放累计最多两个侧向目标，不因重复调用重置。保持 X、Z 和夹爪姿态，Y 沿原有 ±10 cm 策略且绝对值不超过 22 cm。

每次移动后重新获取传感器包、检查夹爪，并等待晚于动作的完整公开关系窗口。使用原有几何与时间阈值判断 verified/failed/unknown。取证不调用释放、抓取或复位，不读取私有真值，也不能跳过最终 Runtime 验证。预算、取消和目标版本检查沿用同一任务。

这是固定中心相机下移动空机械臂以解除自身遮挡的有限策略，不是通用相机视角规划。10 cm 撤离检查仅服务当前已知方块仿真，不能作为任意场景或真机的碰撞保证。需要新相机角度、缺失撤离证据或两次仍不可见时保持 unknown。

## 2026-11-20：撤离与验收条件衔接

手动测试中，最终堆叠在独立物理评分中成立，但 `inspect_placement` 因实测 TCP 比净空要求低约 0.278 mm 而直接返回 unknown。运动接口允许 3 mm 的端点误差，原先把运动到达与严格净空当作可以直接衔接，未给控制误差留出余量。

现在 `inspect_placement` 在最终关系 unknown、释放记录仍有效、空夹爪已确认、姿态及释放竖直路径均有效时，可以先补做一次竖直撤离。目标高度为原净空要求加上两倍当前运动位置容差（当前余量为 6 mm），保持实测 X、Y 和姿态，单次上升不超过 15 cm。低于释放位置超过控制容差、已经进入侧向路径、先前取证失败或已尝试过补撤离时，均不自动补做。

补撤离沿用注册运动接口、累计预算和取消／目标版本检查；每次释放最多尝试一次。等待动作后的新传感器包后，再按原 10 cm 净空阈值检查实际位置和夹爪状态。运动到达本身不构成净空证据。补撤离已使最终关系可判断时立即返回，否则仍只允许累计两个侧向视角；实际净空不够时维持 unknown，不侧移、不重试。

新增 `placement_clearance_retreat_started`／`placement_clearance_retreat_finished` 事件，将释放、取证、代码段 ID 与前后帧、目标／实测位姿、额外调用／运动步／墙钟成本关联。完整事件链和失败状态仍由 `evidence_acquisition_finished` 收束。

测试覆盖控制容差上界、亚毫米净空缺口、补撤离未达要求、路径或姿态变化、夹爪变化、取消、换目标、预算和幂等。真实仿真诊断使用 `experiments.clearance_composition_trial`：在已见种子 62 人为制造释放后遮挡及 4 mm 净空缺口，修复前后各两项；这是工程边界诊断，不能计作自然任务成功率或模型收益。

本轮 Python 193 项、Node 86 项通过。真实仿真对照中，可恢复遮挡从基线 unknown 变为候选 verified；持续遮挡两侧均 unknown，四次独立物理检查成立且没有错误确认。详见[结果与边界](../research/agentic_clearance_composition_20261120/v1/结果与边界.md)。

## 同时修正的证据时序

之前，一张在一秒内采集但早于下降的图像可能通过释放检查。现在放置运动和释放的支撑物证据必须晚于最近完成动作。公开夹爪确认也要求命令和测量来自同一个包，避免把新命令与旧开口拼成空夹爪证据。没有放宽几何阈值。

释放记录与原目标／代码段关联；晚到 worker 不能把旧释放挂到新目标。开始、视角尝试、视角结果和结束事件共用 acquisition ID，额外记录 release ID、证据引用、真实 TCP、接口调用、运动／等待步与墙钟成本。

## 验收

开发版新增 17 项测试使用真实 Episode／解释器／事件路径和现有 CaP 公开验证器，但传感器为 fixture：已可见不动；unknown→verified；unknown→failed；持续 unknown；闭合或缺失夹爪测量禁止移动；未撤离禁止移动；两次后不重复；失去张开状态停止；取消／换目标；目标切换回来仍不可复用旧释放；幂等；累计预算；运动失败；事件导出；下降后不能使用旧图像释放。

2026-11-19 最新开发回归：Python 122 项、Node 42 项通过，含受限竖直撤回、引用帧边界、真实 HTTP 挂起和自主截止关闭。冻结 v2 的最终便携构建三场景 fixture／导出通过，自带 CaP 测试 105 项通过；新增撤回和截止关闭尚未纳入该包。测试数量不代表机器人成功率。

真实 CaP 工程诊断使用单独冻结源码和已见 stack/62，显式注入“释放后绿色 RGB-D 遮挡，侧移解除”以及“释放后持续遮挡”。两项都必须实际进入释放后的技能，未达到则算诊断未覆盖，不能把未运行当通过。全部任务关闭后才独立物理评分。它们不并入无故障 benchmark，也不证明自然遮挡恢复或真实模型会自主选择该技能。
