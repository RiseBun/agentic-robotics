# 状态、任务、技能与执行器统一改造

目标：让机器人基于同一份带证据的状态进行任务决策、技能派发、执行监控和完成验收。Runtime 是物理事实、任务节点和执行状态的权威；工作台和模型读取它，不能另行宣布节点完成。

## 完整验收范围

1. 统一公开状态：对象／关系事实为 verified、failed、unknown，带帧、时间、目标版本与状态引用；旧证据降为 unknown，历史成功不冒充当前事实。
2. 权威任务结构：目标、节点、依赖、所需事实、节点验收及执行尝试关联；完成、待执行、阻塞、失效能区分，换目标不复用旧任务节点。
3. 注册技能：参数、前置条件、后置条件、适用节点及失败出口由 Runtime 定义；常规抓取／放置在技能内部组合原有受限 API，CaP 保留为新问题的受限程序入口。
4. 执行管理：派发时重新检查依赖；模型等待期间新帧不会无条件作废所有决策；取消、目标变化、监控事件和预算能阻止后续动作；失败后的恢复从当前环境与新证据开始。
5. 贯通产品：模型上下文、HTTP 协议、工作台节点展示和导出读取同一个 Runtime 契约；持久化／重连不重放物理动作。
6. 验证：正常任务、同环境恢复、未知证据、迟到决策、换目标、取消、预算、幂等及证据过期的端到端检查。fixture 只证明协议；真实仿真需要独立评分与单独报告。

现有三场景和几何阈值保留。真机具体实现仍留空；本轮不以增加 Agent、微调或自我修改来代替统一执行契约。经验模块后续只能消费关闭任务的统一记录，不取得新的物理控制权限。

## 实施顺序与完成证据

- A：统一状态与任务投影，明确证据新鲜度和任务版本。
- B：技能注册／派发接入同一执行账本，常规操作由技能内部反馈控制。
- C：模型、协调器及界面使用权威任务／技能契约，验证代码入口与技能入口的相同中断边界。
- D：端到端回归、真实仿真诊断、导出及完成审计。

目前为进行中；单项测试、文档或局部技能修复不能作为整个目标完成的依据。后续结果必须逐项回填实际证据与尚未验证的能力。
