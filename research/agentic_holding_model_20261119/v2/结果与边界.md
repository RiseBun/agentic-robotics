两个条件各注入一次执行器打开夹爪，持续 30 控制步。第二项在保持确认后额外持续屏蔽红方块的公开 RGB 与深度。注入由实验后端完成，不作为模型工具提供，不读真值触发。

监控在模型等待期间触发，两个条件各放弃一个正在等待的模型请求；本实验没有覆盖“监控在活动代码段中触发”的模型恢复。故障到监控分别约 1.895 秒、1.992 秒；监控到保持确认分别约 0.027 秒、0.033 秒。不能把后者称为完整故障响应延迟。

可恢复条件下，主模型重新观察、抓取、确认持有并完成原堆叠目标。持续传感器缺失条件下没有误报完成，但模型反复观察和定位，最终由 12 次决策上限结束，**没有证明模型能及时识别无进展并主动请求帮助**。

两项目标均未改变，初始化 reset_count 均为 1，记录中的决策/API 数与累计账本一致，未重置预算；权威墙钟成本分别约 142.34 秒、174.73 秒。错误完成声明均为零。每个条件只有一次，没有算法对照，不构成自然滑落检测、一般恢复率或统计收益结论。

## 暴露的问题与后续修正

持续遮挡条件在故障发生前还出现三次 `nz` 未定义错误；旧解释器会先执行位于错误行前面的动作。这促成全段名称检查：当前解释器在任何 API 前检查未定义变量、未知调用与覆盖 API 名称。

对本轮 11 段代码离线回放，三处此类错误均提前拒绝；扩展到 10 个已关闭 episode 的 72 段代码，共拒绝七处历史同类错误，没有新增拒绝任何原先已完成的代码。回放没有调用机器人 API，不等于物理重跑。物理预检查回归单列于 `../../agentic_program_preflight_20261119/v1/结果与边界.md`。

当前开发版还修正了“新一次抓取继承旧抓空判断”的证据生命周期问题，158 项 Python 测试通过。上述两项模型实验冻结在这两项修正之前，不能声称已实测这些修改后的模型收益。
