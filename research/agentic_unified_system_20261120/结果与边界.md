# 统一架构：协议验收与真实仿真诊断

日期：2026-11-20。架构目标仍在进行中，不能据本轮结果宣布全部完成。

## 已改造的系统职责

Runtime 统一发布带来源、时效和目标版本的三值事实、任务节点、技能与执行状态。模型可选择注册技能；技能和 CaP 程序共用执行器、预算、取消及保持确认。技能要求同时用于任务节点和派发检查，避免节点可执行而实际缺少持有偏移或支撑面边界。最终目标验收与状态投影读取同一份公开结果。

界面区分当前证据、完成时验收与模型建议；旧的完成记录不能覆盖新 unknown。执行记录分别保存程序结果、阶段验证、技能验证与最终目标验证。

## 两次冻结的真实 CaP 诊断

每版均固定三个场景，使用开发种子 12，每场景一次；无 LLM、无静默重试。每个场景创建独立环境，场景内 reset_count 均为 1。重堆叠移障沿用已有受限 CaP 程序，后续由注册技能执行。所有场景关闭后，单独运行评分器读取私有物理记录。

| 版本与任务 | 独立物理完成 | 关闭前公开验收 | 结果 |
| --- | --- | --- | --- |
| v1 / 抬起 | 否 | unknown | 采样姿态对应目标关节跟踪超时 |
| v1 / 堆叠 | 否 | failed | 采样姿态对应目标末端跟踪超时 |
| v1 / 重堆叠 | 否 | failed | 移障完成，随后采样抓取的 IK 残差过大 |
| v2 / 抬起 | 是 | verified | 方块定位顶抓、抬升与持有验证通过 |
| v2 / 堆叠 | 是 | verified | 抓取、放置、释放和最终验收通过 |
| v2 / 重堆叠 | 否 | unknown | 移障、抓取、主动取证完成；下降后支撑证据丢失，释放被拒绝 |

v1 使用 `sample_grasp_pose` 返回的采样姿态。现有控制接受检查拒绝了这些运动，未放宽阈值。v2 改为此前固定程序使用的方块定位顶抓，继续使用相同控制和验证阈值；这限定了技能适用范围，不证明任意抓取采样已经可靠。

v1/job20953 的五秒等待推进仿真 4.95、5.00、5.00 秒；v2/job20954 均推进约 5.00 秒。各场景接口账本与事件计数匹配，公开最终判断与统一状态中的目标事实一致；两版均无错误完成声明。独立物理结果要求关闭前至少 0.5 秒窗口的多个样本一致，不保证未来长期稳定。

两版分别保留源码摘要与评分结果：[v1](v1/independent-summary.json)、[v2](v2/independent-summary.json)。重复出现的 episode_id 必须与运行版本／归档哈希一起识别；它们属于两个独立冻结目录，不是同一环境的重放。

## 协议和产品证据

- HTTP → Node 协调器 → Python 解释器 → Runtime 验收 → 导出已贯通，使用确定性模型替身。
- Electron 桌面三个场景：原 CaP 路径 6 次模型请求；注册技能路径 8 次模型请求，均完成协议任务并可导出。此 fixture 不模拟真实重堆叠难度。
- 覆盖未知依赖、错误参数、幂等、过期证据、停止、换目标、预算与重启中断；确认环境不因任务内分段而复位。
- 新注册的 `retreat_from_descent` 位于 v2 冻结之后：已有合成传感器测试确认低位持有 unknown 时，仅根据现有反向路径授权撤回，随后重新验证持有；路径失效时不派发旧动作。该注册恢复入口尚未获得真实仿真／模型能力证据。

## 不能推出的结论与下一步

开发种子诊断不构成成功率，也不证明模型会正确选择注册技能。v2 的两项完成不能覆盖重堆叠失败；v1 失败也不能删除或合并到 v2 后重新计算总体收益。

下一步先验收注册恢复节点在真实场景中的状态、动作和预算一致性，再接通移障及 CaP 段的任务绑定，最后做真实模型的端到端选择／恢复评测。未知证据下拒绝释放仍保留，不通过增加预算或放宽阈值替代恢复能力。
