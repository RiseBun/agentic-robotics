作业 20777，模型 gpt-5.6-sol。两项从原始 cube_stack/70 用户目标开始，不人工准备到恢复阶段；全部关闭后才导出和独立评分。两项关闭、模型进程正常退出后取消服务作业释放 GPU，因此 Slurm 的 CANCELLED 是服务清理状态，不是模型试验中断。

## 实现

Runtime 在代码段保存接口调用 ID、参数、执行结果摘要和错误类别，不依赖 SSE 是否及时送达。工作台向同一个主模型提供相关公开事实、缺失证据、尝试记录及有限恢复路径。换 frame ID、时间戳或计划措辞不算进展。

相同事实下，重复已失败的同一代码会被阻止；持续缺证据时重复 observe/finish 也会被阻止。不同、适用的恢复代码仍可提出，最终由 Runtime 检查技能前置条件。模型 ask_user 和系统重复保护分开记录；两者进入等待用户状态前均须确认保持。

这不证明能识别任意两段语义相同的 Python。改写代码仍可能绕过同代码检查，最终仍有原任务预算约束；没有获得一般性的无循环保证。

可恢复条件下重新确认持有一次，监控重新布防，然后完成原堆叠目标。公开审计记录一次最终物体释放，其前置支撑证据 available；没有未知支撑证据下的最终释放。

持续缺观测条件在监控后提出三次 observe，随后主动请求帮助，未触发系统重复保护，决策预算剩余两次。模型请求恢复红方块可见性，建议把方块移回视野；这没有识别人工屏蔽的传感器故障，具体人工操作能否解决故障未经验证，不能称为根因诊断。

## 限制与版本区分

- 这是同一历史种子 70 的两条件回归，各一次。没有同轮算法对照，模型输出有随机性；不能将历史“12 次耗尽”与本轮“10 次请求帮助”解释为统计收益。
- 故障是显式执行器与像素屏蔽注入，不是自然滑落或真实遮挡。两次监控均发生在模型等待期间，仍缺活动代码期间监控后的主模型恢复证据。
- 冻结模型版对应 Python 159、Node 70 项工程测试。它用厘米分箱判断位置变化，并从历史取证结果推测视角次数；本轮没有调用主动取证技能，不能证明这部分决策正确。
- 后续开发版把视角剩余状态改为 Runtime 当前协议元数据，避免新抓取沿用旧取证次数；位置改为显式每轴 0.01 米容差，避免跨舍入边界制造进展。容差只用于重复判断，不改变几何验收阈值。开发回归 Python 160、Node 72 项通过；这两个修改没有包含在本目录两项模型冻结中，不能借用本次模型结果证明修改后的模型表现。
- 新的全段预检查物理回归作业 20778 覆盖当前 Python 版本，零错误代码 API，修正后独立持有结果 verified；它不调用主模型，也不是本项恢复策略的收益实验。
