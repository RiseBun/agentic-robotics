# Bounded alternative after safe retreat

Goal: test an actual alternative recovery route rather than changing the success declaration or simply retrying the same blocked release. Scope is two-cube simulation; no general collision guarantee or cross-hardware claim.

Opt-in CAP_ALTERNATE_PLACEMENT exposes reorient_held_object only on its dedicated task node. Eligibility requires a rejected release in the current goal, verified current holding, valid holding geometry, no pending recorded low retreat, and an observed high-clearance envelope. The envelope requires bounded XY and clearance above the other cube after accounting for the held cube extent. A yaw candidate rotates about the current TCP without translation or release, then checks holding. At most two attempts (+25 degrees, then -50 relative to the first yaw) are recorded per goal. Every attempt, including failed ones, consumes the allowance. The shared interpreter, goal fence, stop hold and cumulative budgets still apply.

The node accepts only the registered skill, not arbitrary bound code. Failed release records remain; new holding geometry and fresh support evidence are needed before another placement. Orientation change is an alternative hypothesis, not proof of repaired placement or task completion. Production opt-in remains disabled until physical and model validation.

Early diagnostic directories are retained. v1/v2 candidate traces stopped at empty-gripper verification because a new feature-flag block was incorrectly duplicated into CaPBackend.verify, referencing an undefined state. Removed it and added a direct real-method regression. v2 also adds a bounded three-second public-readiness wait to both conditions. v3 reached retreat, but no yaw node was ready because trigger depended on noisy retry-context equality. v4 uses actual rejected-release history. A further test identifies that failed rotation attempts must not count as successful resolution of that release. These are development findings, not success-rate samples.
