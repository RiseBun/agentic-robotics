# 跨计划恢复准入：实现与验收

日期：2026-11-26。只修改 Thor，生产服务未切换，经验保持关闭。

## 问题与改动

上一轮真实模型在低位释放证据不足后反复选择撤回—再次放置，直到 24 次模型预算耗尽。计划节点重建和短代码换写法不应被当成新的恢复策略。

新增 Runtime 准入：对同一目标版本、注册操作参数和恢复条件，最多容许两次没有验证效果的执行尝试，之后阻止同一操作。计数跨计划和节点名保留；不计取消、执行中的段、已验证成功及尚未产生公开调用的前置拒绝。

放置条件忽略持有物自身搬运位置和无关物体版本变化，记录相关支撑物版本、最近已验证抓取、相关有效主动视角动作。新时间戳、被动观察、单纯撤回不清零。不同目的地、相关物体变化、新验证抓取或实际有效视角生成不同条件。它们仍需原有前提和权限，模型不能声明条件已经改变。

节点公开 retry_constraint；强行提交返回 HTTP 409 / RECOVERY_BLOCKED 并记录 recovery_dispatch_blocked。技能、绑定代码、直接 CaP 共用准入。工作台收到拒绝后请求 Runtime 保持确认并进入用户协助状态。

## 工程与故障验收

- Python 411 项、Node 132 项通过；新增 Python 9 项与 Node 1 项。
- 认证 HTTP fixture 故障：两次放置失败，中间撤回一次；重建节点后技能和短代码均返回 RECOVERY_BLOCKED。
- 被阻止请求新增公开调用 0、新增运动步 0、新增代码段 0。
- 原请求重复返回原执行 ID；停止确认通过，全过程同一个环境实例。
- 被动观察不解锁；真正执行并获得 available 的相关视角可重新评估。无关观察、unknown、取消和目标版本边界有测试。

fixture 故障结果只证明协议和执行边界，不算物理成功，也不证明模型能自己找到有效恢复。

## 限制与后续

- 当前最多两次是开发期保守执行规则，不是从统计结果学习出的最优重试次数。
- 实际有效视角表示改变了取证动作，不保证缺失事实已经修复；重新准入仍检查原证据和技能前提。
- 模型仍可能花费决策预算反复提出被动计划/观察；本轮保证重复物理操作被阻止，没有实现全局最优恢复。
- 仅在通用桌面模式生效，未添加真机、ROS 2、多机器人或模型训练。
- 下一步冻结一个真实模型故障场景，检验它是否能在看到限制后选取新的取证路线或及时请求帮助，再扩大物理回归。
