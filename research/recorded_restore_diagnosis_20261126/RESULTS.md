# 记录路径恢复失效：根因诊断与固定现场规划

日期：2026-11-26。基于221864d，在Thor开发。生产服务未切换；未修改原恢复准入条件、几何阈值或动作预算。

## 已查明的阻塞

fault202-v1复现了恢复拒绝：下降记录存在、对象与目标版本匹配、夹爪闭合、终点编码器匹配，唯一失败项是scene_versions_match。记录下降时平台版本为0，释放被拒时变为1。关节最大误差约0.00057rad，小于原0.05rad条件。

| 条件 | 结果 |
|---|---|
| 下降记录存在 | 通过 |
| 对象匹配 | 通过 |
| 目标修订版本匹配 | 通过 |
| 夹爪闭合 | 通过 |
| 编码器与轨迹终点匹配 | 通过 |
| 场景版本匹配 | 未通过：platform 0→1 |

任务关闭后的独立物理记录显示平台全程XY变化小于1e-12m，Z变化约1.03mm；下降到释放拒绝这一窗口的精确数值见audit.json。该物理记录只用于离线归因，没有用于模型、感知或规划。

当前感知代码把当前可见表面中位点相对baseline变化超过2cm计作object_versions变化。遮挡会改变被测到的表面区域，不等价于物体刚体位姿变化。本例的场景变化信号存在误拦证据；不能据此删除版本条件，或宣称所有版本变化都是误判。

## 实现

- recorded_descent公开验收增加逐项checks、blockers、关节误差和变化对象的原/现版本，原判断逻辑不变。
- 下降完成记录recorded_descent_saved；释放验收同时保存当时的restore_admission，避免后续现场变化掩盖当时原因。
- 开发故障适配器增加默认关闭的RGBD_RESTORE_PLAN_PROBE=1。只在旧记录唯一阻塞为场景版本、当前持有verified时探测重新规划；没有轨迹派发，不放行旧记录。

1600组确定性记录/关节/版本组合的准入结果与原逻辑一致；5项恢复诊断和4项只规划测试通过，含原终点阈值、取消传播和禁止运动断言。完整Python472项、Node132项通过。

## 在线复现与固定现场的区别

v1同开发种子复现了版本阻塞，但不是精确历史轨迹重放。v2-probe的模型和感知轨迹不同：探测当时旧记录有效，持有证据unknown，因此按规则not_attempted。不能把这条记录算作重新规划失败，更不能用多次同seed运行冒充相同失败现场对照。

随后固定v1释放拒绝对应的公开归档相机帧、配对机器人状态和已记录的下降前目标位置，执行独立离线规划。脚本plan_frozen_scene.py不读取私有物体真值，也不连接执行器；输入文件SHA256记录在frozen-scene-planning.json。

## 固定现场规划结果

目标为先前approach位置，Z约0.99475m；原低位目标Z约0.86475m，相差0.13m。采用归档公开点云及配对关节状态：

| 输入 | 规划结果 | 轨迹点 | 执行 |
|---|---|---|---|
| 主视角，未剔除持有物 | 返回collision_aware轨迹 | 27 | 否 |
| 腕部，未剔除持有物 | 返回collision_aware轨迹 | 27 | 否 |
| 腕部，重新SAM分割剔除持有物 | 返回collision_aware轨迹 | 27 | 否 |

两条未剔除点云路径减少了对重新分割结果的依赖，但仍不是物理运动验证。重新SAM得到的mask并非原始mask；缺失深度没有补成空闲空间。规划器检查范围仍为观测场景和机器人，不建模携带物碰撞，未验证轨迹跟踪、运动中的持有或撤回后的支撑面验收。

因此只能得出：**固定归档现场存在规划器可接受的撤回候选，旧证据失效与规划无解是两回事。** 不能声称已修复自主恢复。

## 下一步

保留原restore_grip_pose语义。把“当前证据重新规划撤回”设计为独立、显式注册的恢复操作，目标只能绑定已记录的下降前位姿；由S2选择，经当前持有、目标版本、实时规划、场景变化、取消及累计预算检查后才能派发。先验证撤回过程中的持有与执行，再检查撤回后能否补足支撑面。

不得为了让旧反向路径通过而直接忽略场景版本变化，也不应把规划成功当作已执行成功。需分别处理观测变化与真实物体变化；当前版本机制的误拦仍在，没有通过离线真值纠正在线决策。
