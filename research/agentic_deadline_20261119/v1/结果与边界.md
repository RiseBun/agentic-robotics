# Runtime 截止收敛：实现与物理诊断

2026-11-19，作业 20749，正常结束，用时 42 秒。部署包 SHA256 `215b3871d7b0c27dc80a7ca9a32cc2384c502df713520eeb95eed20567cac1f7`。本轮不调用模型，不做机器人任务成功率或私有物理评分。

## 根因与修改

原实现达到墙钟预算后会取消代码、切换到保持，却持续推进空闲仿真，直至客户端回来关闭。这导致断线后的场景寿命与成本无界增长。

现在由唯一物理控制线程执行完整终止序列：

1. 预算到期，禁止新动作，取消当前代码，登记保持请求。
2. 控制线程将目标切换为当前关节与原夹爪命令，推进并确认保持。
3. 可取消执行器完成当前段的取消记录；后端工具构建也纳入可取消等待，避免在工具初始化期间挂起。
4. 自动写入 closed、termination_reason=wall_budget_exhausted，冻结任务成本并释放物理环境。

重复 close 不重复记账；终止后的新执行拒绝接收。后续开发版还拒绝改写终止任务的目标，避免重连后破坏历史记录；工作台刷新到 Runtime 截止状态时，作废迟到模型回复并明确显示任务已结束。这两个后续边界改动不在本轮物理冻结包中，已由单元测试覆盖。
